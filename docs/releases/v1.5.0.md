# WUTNet v1.5.0 — Windows scheduled recovery and static analysis

Windows release, 2026-10-23. Android remains the separate experimental v1.4.0 artifact; this release contains no new APK. Historical releases, tags and assets remain unchanged.

## Changes

- `install` generates a managed UTF-16 VBS launcher under `%LOCALAPPDATA%\WHUT-Net`, dynamically resolves script/PowerShell/WSH paths, validates a harmless launch, then creates or updates **WHUT-Net AutoLogin**. `wscript.exe` hides PowerShell, waits and propagates its exit code. Task Hidden is only a Scheduler visibility setting.
- Five native triggers: current-user logon (5-second delay), NetworkProfile/Operational 10000 (3 seconds), current-user unlock (3 seconds), System Power-Troubleshooter 1 (3 seconds), and daily recurrence from local midnight with a two-minute interval and one-day duration every day.
- InteractiveToken, least privilege, IgnoreNew, a two-minute process limit, mutex, cooldown and backoff remain. Unknown networks are never automatically enrolled; authentication and credential protection are unchanged.
- Uninstall failures preserve config, DPAPI credential, logs, auto state and launcher; deletion follows successful task removal or confirmed absence. This includes the source fix absent from historical v1.4.0 assets.
- Approved `Stop-Whut` / `Initialize-WhutDataDirectory` helpers, targeted advanced-function interfaces and explicit command/parameter validation. Unsupported combinations return 50; public command names, JSON fields and existing exit meanings remain.
- PSScriptAnalyzer 1.23.0 development/CI gate, plus synthetic task/launcher regressions and safe local WSH/COM validation. No runtime analyzer dependency or Phase 3 WhatIf/Confirm feature.

## Download and upgrade

Assets: `whut-net.ps1`, identical `whut-net-v1.5.0.ps1`, and `SHA256SUMS.txt`. Verify the exact filename's complete SHA-256, keep the script in its stable location, then explicitly rerun the new script's `install` to migrate an existing direct PowerShell/manual VBS task. Existing credentials and trusted networks are retained. If WSH/VBScript is missing or policy-blocked, resolve that with the system administrator; no policy is changed or visible-console fallback installed.

The tracked `whut-net-v1.4.0-fixed.ps1` remains a byte-identical source compatibility alias and reports 1.5.0; it is not the old published asset. The v1.4.0 tag and downloads retain their original bytes and behavior.

## Evidence and limits

See [field validation](../FIELD_VALIDATION.md) for dated authentication/reconnect observations and supplied historical hidden-window/unlock acceptance. New offline regressions and safe WSH exit-37/COM XML validation do not constitute real-device sleep-resume or periodic-retry acceptance. No real credentials, campus authentication or real task registration are used in automated checks. Windows Script Host/VBScript is required only for optional automation. WHUT still uses HTTP; DPAPI protects storage only. Android device authentication remains unverified.

Validation commands, analyzer exceptions and the CI matrix are documented in [Contributing](../../CONTRIBUTING.md). [Windows guide](../WINDOWS.md) contains the exact command matrix, trigger definitions and failure recovery procedure.
