# v0.1.1 — Windows reliability and security (draft)

Status: release notes only. Do not publish a stable Release until the complete current
WHUT authentication flow has been field-tested again. Android is unchanged.

- Replace single-site portal discovery with NCSI redirect/content, NeverSSL and direct
  WHUT probes. Independent 4-second timeouts share a 16-second discovery request budget.
  Internet preflight adds at most 8 seconds. Untrusted redirects fail closed.
- Store config v2 with the physical route/interface, actual IPv4 prefix, gateway and
  portal host. Profile suffix and DHCP host-address changes no longer break auto-login.
  Config v1 remains readable; rerun `setup` on WHUT before using `auto`/`install`.
- Decrypt DPAPI credentials only immediately before the dedicated login POST. Form
  encoding uses mutable buffers, cleared on success/failure; no explicit plaintext
  password .NET string or generic form object is created.
- Centralize known protocol endpoints/codes and validate CSRF/status/login JSON shapes.
  Accept `/api` fallback only after active CSRF validation; validate status before POST.
- Add exit 13 for unsupported/changed protocols and 31 for exhausted timeout discovery.
  Authentication rejection remains 20; transport/API failures are not bad-password errors.
- Add dependency-free offline PowerShell tests, parser checks and Windows CI with a
  lightweight tracked-secret/ignore-rule guard.

Security limits remain: HTTP has no transport confidentiality, DPAPI protects storage
only, runtime/HTTP-stack copies cannot be guaranteed erased, and network/protocol
fingerprints do not cryptographically authenticate WHUT.

## Field validation still required

- Capture a genuine unauthenticated WHUT redirect and session `nasId` via the new probes.
- Confirm live config, CSRF/cookie, status and login response shapes, including errors.
- Verify account-online **and** Internet recovery after submitting a real credential.
- Exercise profile suffix changes, DHCP renewal, gateway/subnet changes, simultaneous
  adapters and scheduled logon/network-connect auto-login with a v2 fingerprint.
- Confirm timeout behavior and direct-only reachability when individual public probes
  are filtered. A reachable login page without `nasId` must not submit a password.

Local tests use only synthetic credentials and mocked transport; they do not establish
real WHUT authentication success.
